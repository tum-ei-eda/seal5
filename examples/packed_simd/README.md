# Packed SIMD with ordinary TableGen patterns

The integrated demo supports RV32 packed add/subtract on four 8-bit lanes and two
16-bit lanes. It generates ordinary `Pat` records; `gisel_table` is disabled.
`GPR32V` (`+gpr32v`) enables packed register representation. The instruction rules
also require the demo ISA feature `+xpackedsimd32`.

The matching CoreDSL2LLVM branches are `llvm-22.1.8-packed-simd` and
`llvm-23.1.3-packed-simd`. They are local branches until published. With a local
CoreDSL2LLVM checkout containing those branches:

```sh
source venv310/bin/activate
REPO_URL_CoreDSL2LLVM=file:///work/git/CoreDSL2LLVM LLVM_REF=llvmorg-22.1.8 \
  TEST=1 INSTALL=0 DEPLOY=0 EXPORT=0 python examples/packed_simd_demo.py
# Repeat with LLVM_REF=llvmorg-23.1.3
```

There is one handwritten codegen test per instruction, plus autogenerated tests
and a fallback regression file.
The verified subset selects with both GlobalISel and SelectionDAG. Additional
checks cover O0/O2/O3, subtraction operand order, aligned/unaligned transfers,
object decoding and feature gating. Against an already built demo backend:

```sh
python examples/packed_simd/check.py /path/to/build/bin check /tmp/packed-check \
  --extension xpackedsimd32
```

For standalone backend development, `check.py BIN prepare OUTPUT` emits the four
fixture definitions and format includes. Build those includes into the backend,
then use `check.py BIN check OUTPUT` without `--extension`.

`fixtures/` contains lane-wise CoreDSL and scalar-ABI/vector-bitcast IR examples.
`probe.py` and `baseline-llvm22-23.json` preserve the initial unsupported baseline;
a successful probe-script exit means collection completed, not that all probes
passed. Reproduce that collection with `--llvm22-bin`, `--llvm23-bin`, and
`--output` arguments.

RV64 and the broader LLVM20 SIMD experiments (shifts, multiplication, min/max,
comparisons, unpacking, reductions and dot products) remain outside this verified
subset. See [the investigation and port report](../../docs/packed-simd.rst).

## Embench vectorization experiment

`embench.py` compiles unmodified scalar C from an external Embench tree. It
compares scalar, native O3, and packed O3 optimization, then tests both selectors.
It records vectorizer remarks separately from actual packed object instructions.

```sh
python examples/packed_simd/embench.py \
  --source /path/to/embench-iot \
  --headers /path/to/riscv-newlib/include \
  --llvm22-bin /path/to/packed-llvm22/build/bin \
  --llvm23-bin /path/to/packed-llvm23/build/bin \
  --output /tmp/seal5-packed-embench
```

Each bin directory needs `opt`, `llc`, and `llvm-objdump` built with this demo
model. Clang defaults to the same directory; use `--llvm22-clang` and/or
`--llvm23-clang` to supply another matching-version frontend. The patched
optimizer is essential because it supplies the packed vectorization cost model.
Optional `--benchmarks edn md5sum picojpeg` restricts the source set; `--variants`
restricts configurations. A zero exit means collection completed, not that all
compilations passed. No benchmark is linked or executed by this script.

[Current verified results](results/implemented-llvm22-23.md): complete benchmarks
now compile and execute with packed instructions. The
[initial negative result](results/embench-llvm22-23.md) is retained for comparison.


## Benchmark execution and verification

GPR32V describes register representation. The generated ISA feature also implies
its `gpr32v-add` / `gpr32v-sub` backend capabilities, configured through
`backend_features` in `cfg/passes.yml`. Normal compilation enables
`+gpr32v,+xpackedsimd32`; the standalone fixture verifier enables operation flags
explicitly.

The benchmark runner defaults to a strict-alignment target. To evaluate a target
with efficient unaligned scalar accesses, add `--memory-model unaligned` to the
compilation command above. Apply that choice to the scalar controls too, as the
runner does. No vectorization thresholds are forced.

Execute the resulting artifacts with a matching Spike build and RISC-V GCC/Newlib:

```sh
python examples/packed_simd/execute_embench.py \
  --results /tmp/seal5-packed-embench/results.json \
  --gcc /path/to/riscv-toolchain/bin/riscv64-unknown-elf-gcc \
  --spike /path/to/spike-build/spike \
  --spike-source /path/to/riscv-isa-sim \
  --spike-build /path/to/spike-build \
  --output /tmp/seal5-packed-executed --repetitions 3
```

The runner builds the demo extension against that Spike build's C++ headers,
checks instruction semantics and generated fallback code against independent
scalar references, links complete benchmark programs, executes them, and checks
Embench's verification functions. The extension interface requires the matching
Spike ABI. The tested Spike supports `Zicclsm`, used when the compilation selected
the unaligned-capable memory model. `--benchmarks edn md5sum` restricts execution.
A zero runner exit means collection completed; inspect each record's link and
verification results. Skipped compilation failures remain explicit in the data.

The counters record retired instructions and Spike CPI=1 model cycles. They do
not measure hardware latency or independently establish cycle speedups. The
runtime uses a 128 MiB RV32 bare-metal memory layout, Newlib and HTIF termination.

To ensure cost changes have not hidden a lowering failure, replay previously
optimized IR without running the optimizer again:

```sh
python examples/packed_simd/replay_embench.py \
  --results /tmp/earlier-embench-run/results.json \
  --llvm22-bin /path/to/packed-llvm22/build/bin \
  --llvm23-bin /path/to/packed-llvm23/build/bin \
  --output /tmp/seal5-packed-replay
```

These commands require the artifact directories from the compilation run, not
just the committed result snapshots. The snapshots provide measurements and
provenance; object files, linked executables and full logs stay in the run output.
